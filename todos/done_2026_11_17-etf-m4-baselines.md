# ETF M4 비교 기준선 구현

> 유형: implementation
> 상태: 완료 — 최신 CPU538개·예제4개·M3대조153개 PASS, SOL·Opus 리뷰 보완 완료
> 사용자 지시: M4 비교 기준선도 M3와 같은 구현·검증·리뷰 절차로 진행

목표는 같은 바스켓·비용·환전·결제·평가 시각에서 분할매매와 비교할 월별 리밸런싱,
단순 보유, 투자 비중 0·25·50·75·100% 프런티어를 제공하는 것이다.
상위 계약은 [연구 계획 5절](2026_11_15-etf-vol-split-research-plan.md#5-비교-기준선)과
`protocol_v1.json#baseline`이다. M5의 학습 기간·탐색 격자는 이번에 임의 확정하지 않는다.

쌍대 성과 보고와 외부 연결 없는 예제를 구현했다. 일반 CPU/GPU 제품 전략과 M3 C++ 후보는 바꾸지 않았다.

검증을 수행했다는 뜻은 아니다. 코드는 [사용 안내](../docs/research/etf_m4_baselines.md)에서 시작한다.

## 범위와 불변조건

- 주 기준선의 비중은 명시한 학습 구간의 평가 시각별 `투자액 / 장부 평가액` 산술평균으로 고정한다.
  가중은 동일가중 또는 학습 시점까지 알려진 변동성의 역수다. 평가 자료로 맞춘 비중은 진단 전용이다.
- 학습 종료·가중 정보 시각은 평가 시작보다 이르다. 고정 정책과 학습 행의 해시를 보존한다.
  학습·평가 기간은 호출자가 명시하며 미래 행·다른 바스켓·중복 시각을 거부한다.
- M2 사건·현금·환전·결제·기업행사·세금 원장을 재사용한다. 기존 분할매매와 C++ 후보는 바꾸지 않는다.
  월 첫 통합 세션에서 직전 명시 평가액(최초에는 초기 자산)으로 원화 목표를 고정하고 각 시장의
  그달 첫 개장 시가에 정수 수량을 주문한다. 같은 시각 매도 후 매수, 각 종목 하루 한 주문이다.
- 시가 체결·슬리피지·거래량 0·가격 제한·참여율·현금 부족 거절을 유지한다. 부족 주문을 줄이지 않는다.
  단순 보유는 첫 진입만 하며 분배금을 현금으로 받고 재투자·월별 환전을 하지 않는다.
- 리밸런싱의 부분 매도는 취득 건별 수량을 줄이되 세무 원가는 기존 종목별 이동평균을 쓴다.
  여러 취득분을 한 주문으로 파는 경우만 세무 원장에 묶음 매도 API를 추가한다. 기존 단일 매도
  계약과 같은 날 복수 국내 기타 ETF 매도 제한을 유지한다.
- 주 결과의 현금 이자는 기존처럼 0%다. 실제 세후 승인·상폐 청산·국내 T+2 등 M5 선행 조건은 유지한다.
- 지표는 실제 경과 시간 CAGR, 초기 자산을 포함한 MDD, Calmar, 수중 기간, 평균 투자 비중,
  거절 수, 종료 미실현 가격손익이다. 쌍대 차이는 ΔCAGR=전략−기준선,
  ΔMDD=|기준선|−|전략|로 고정한다. 같은 평가 시각을 강제한다.

## 구현·검증·검토 순서

1. 정책 고정·학습 시각 검증과 기준선 실행부, 세무 묶음 매도를 구현한다.
2. 금융 원장의 위험 통합 지점에서 `sol_reviewer` 읽기 전용 REVIEW를 받는다.
3. 손계산(초기 매수·월별 일부 매도·추가 매수·수수료·분배·환전·결제), 미래 자료 변경,
   0/100% 비중·불변가·두 장중 경로·부분 세무 매도를 검증한다. 프런티어/쌍대 지표를 연결한다.
4. CPU 전체·실행기 자체 검사와 M3 정확 대조를 수행하고 최종 필수 리뷰의 차단 결함을 해소한다.
5. 같은 방식으로 Opus 최종 읽기 전용 리뷰를 제출한다. M3 Opus 작업은 별도 유지한다.

완료 조건은 위 합성 검사·기존 회귀 통과, 검토 차단 결함 해소, 사용 예제와 근거 기록이다.
실자료 최적화·보류 평가·전략 수익성 승인은 범위 밖이다. 계약 변경이 필요하면 원인을 기록하고
검토한다. 중단·예산 소진은 완료가 아니며 재개 시 소스 해시·로그·리뷰 상태를 대조한다.

## 실행·검토 이력

아래는 보존한 실행 순서이며 이후 항목이 앞선 대기·검증 상태를 대체한다.

- 시작 기준: `e241371`, M3 변경이 미커밋으로 존재한다. 그 변경을 보존한다.
- 작업 시작 당시 M3 Opus Dispatch `ctx_1ef220491fda`는 `input_accepted / live / working` 상태였다.
- 핵심 구현·프런티어·쌍대 지표·합성 실행 예제·CPU 검사 목록 연결을 완료했다.
- 위험 통합 `sol_reviewer` REVIEW에서 US 기본 SEC 요율 경로(P1), 누락 변동성의 암묵적 대체(P2)를
  지적했다. 공통 결제일 요율을 전달하고 모든 변동성 추정값을 요구하도록 수정했으며 각각 회귀 검사를 추가했다.
  다중 취득분 묶음 매도·이동평균 원가에는 추가 결함을 찾지 못했다.
- `core-r3.log` 핵심36개 PASS, `report-r1.log` 지표14개 PASS. 기존 세무35개 초기 검사도 PASS다.
  두 경로 예제 결과는 `results/etf-m4-validation/demo-{ohlc,olhc}-r1.json`이다.
- `runner-r1.log` 실행기 자체24개, `cpu-r1.log` 선택CPU530개·예제4개,
  `native-r1.log` M3 정확 대조153개가 모두 종료0·누락/건너뜀 없이 PASS다.
  이번 M4 실행은 새 C++ 컴파일 없이 M3의 검증된 `build-v2`를 사용한다. M4에서 C++ 소스는 바꾸지 않았다.
- 소스 지문은 `results/etf-m4-validation/source-r1.json`(14개 파일)이다.
  검사 후 같은 해시를 재확인했고 로그 SHA·집계를 `validation-summary-r1.json`에 보존했다.
- M3 Opus 완료: P1/P2 없음, 합성5,500건 M2 수치 동치. Decimal 문자열 표현과 진행판 P3는 보완했다.
- 다음 행동: 전체 로그 확인·최종 필수 리뷰·Opus 최종 읽기 전용 리뷰.
- 첫 최종 SOL 리뷰에서 같은 ZoneInfo의 서머타임 벽시계 차이를 실제 경과시간으로 사용한 P2를
  발견했다. 정책·학습·평가 시각을 UTC로 정규화하고 봄47시간/가을49시간·반복 시각 순서·동일 순간의
  UTC 표현 동치 검사를 추가했다. `core-r4.log`38개·`report-r2.log`16개 PASS다.
- 서머타임 보완 뒤 지문은 `source-r2.json`이다. r1 대비 정책·보고·두 검사만 바뀌었다. 기존 원장/C++/실행기
  의존 소스가 같아 `native-r1.log`153개와 `runner-r1.log`24개를 재사용하고 전체CPU는 `cpu-r2.log`로 재검사한다.
- SOL 수정 확인에서 DST P2 해소·추가 차단 없음으로 확인했다. 봄/가을 경과시간·fold 순서·원본 행
  불변과 source-r2 지문, 핵심38개·보고16개 통과를 검토했다. 전체CPU-r2 종료 결과는 메인에서 확인한다.
- **r2 전체 검증:** `cpu-r2.log` 선택CPU534개·예제4개가 엄격 집계에서 모두 종료0·누락/건너뜀0으로
  PASS다. source-r2 해시 불변을 재확인하고 `validation-summary-r2.json`에 로그 SHA·재사용 근거를 남겼다.
- **Opus 최종 검토 시작:** 같은 Opus 5.5/xhigh 읽기 전용 터미널의 준비 상태를 확인하고 M4 새 Task
  `task_51a4894dc2ee`를 제출했다. Run `run_8fe20dc790c3`, Dispatch `ctx_3699da358dfd`, `state=ready`다.
  요청서는 `results/etf-m4-validation/opus-review-spec.md`, 시작 근거는 `opus-start.json`이다.
  M3 리뷰와 별도 작업으로 제출했다. 커밋·push·원격 CI는 하지 않았다.
- **Opus 전체 리뷰 완료:** Dispatch `ctx_3699da358dfd`가 `worker_done / succeeded`로 보고했다.
  source-r2의14개 지문·공유 원장·프런티어·지표·검사·문서를 대조했고 P1/P2는 없다.
  수치·체결·미래 정보 계약에서 추가 결함을 찾지 못했다. 보고는 `opus-review-r2.json`에 보존했다.
- P3 두 건은 `opus-p3-repro.log`로 먼저 재현하고 수정했다. 정책 평균·가중·검증은 정밀도80·
  HALF_EVEN으로 고정해 8가지 호출자 반올림에서 유효 입력과 해시가 같게 했다. 원래 호출자 문맥과
  체결 연산은 유지한다. 세무 원장은 상품 검사를 취득분 접근보다 앞에 두어 기존 ValueError를 복원했다.
- `core-r5.log`42개·`tax-r3.log`35개 PASS다. 최신 `source-r3.json`은 정책·세무·핵심검사3개가 바뀌었다.
  `cpu-r3.log`538개·예제4개와 `native-r2.log`153개 재검사가 모두 종료0으로 통과했다.
- SOL의 source-r3 수정 범위 리뷰에서 호출자 반올림/정밀도 보존, 정책/해시 안정성, 시점 정보 검사,
  잘못된 상품의 ValueError 복원과 유효 매도의 원장 불변을 확인했고 추가 차단이 없다.
- 검사 종료 후14개 소스 해시를 다시 대조했다. 이전 실패·r1/r2 결과를 덮어쓰지 않고 최신 집계를
  `validation-summary-r3.json`에 남겼다. `git diff --check`도 통과했다.

## 다음 단계와 재개 조건

M5 탐색 전에는 상폐 청산·국내 T+2·혼합시장 환전·환율 최대 경과일·공통 평가 달력·제품 하락률
유효성 등 [기존 선행 조건](2026_11_15-etf-vol-split-research-plan.md#M2-이후-실행-조건)을 충족해야 한다.
M5 학습 기간·실행 기간·바스켓 구성·격자, 완결 세후 보고·금리 민감도·보류 판정은 이번에 정하지 않았다.
새 정책 규칙·원장·시각·시장표 변경이 생기면 해당 손계산·최신 전체 검증·필수 리뷰를 다시 연다.

## 목표와 승인 범위

가상 종목 하나와 명시적 7거래일로 신규 매수 → 추가 매수 → 부분 매도 → 전량 매도와 현금·자산 계산을 재현한다. 사용자는 2026-11-06에 아래 계획의 구현·원격 검사·일반 merge·공개 확인을 승인했다.

- 실제 CPU 엔진·MagicSplitStrategy·체결·Portfolio를 사용한다. 예제용 메모리 조회기만 추가한다.
- DB·GPU·외부 계정·제품 YAML/INI 없이 실행한다. 지표·종목 등급은 사전 구성한 가상 입력이며 SQL·후보 산정·전체 전략 유효성 검증이 아니다.
- 기본 콘솔 표, 선택 CSV 두 개, 새 경로만 저장·기존 파일 보존. Release는 발행하지 않는다.
- #21은 CPU 경로 설명 보강과 원래 요구 대조까지다. 남은 DataHandler·GPU 설명은 유지한다.
- 제품 매매·체결·자산 계산·DB API·스키마·운영 데이터·GPU·전체 환경 이관은 변경하지 않는다.

## 고정 시나리오와 기대값

가상 종목 `SYNTH001`, 날짜는 2024-01-02/03/04/05/08/09/10이다. OHLC는 순서대로 (10000,10100,9900,10000), (10000,10100,9400,9500), (9400,9600,9300,9400), (10000,10500,9900,10400), (10400,11200,10300,11100), (11100,11200,11000,11100), (11100,11200,11000,11100)이다.

초기 현금 1,000,000원, 주문 비율 10%, 종목 1개, 최대 분할 2회, 하락 5% 추가 매수, 개별 매수분 10% 익절, 재진입 대기 5거래일, 손절 -15%, 비활성 기준 90거래일, lowest_order/strict_hysteresis_v1/tier/조회 오류 raise를 사용한다. 매수·매도 수수료 0.00015, 매도 세금 0.0018은 기존 계산 모델의 예시이며 현행 법정 요율 주장과 구분한다.

| 거래일 | 동작 | 수량 | 가격 | 수수료 | 세금 | 이후 현금 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 01-03 | 1차 매수 | 10 | 10000 | 15 | 0 | 899985 |

| 01-08 | 2차분 매도 | 10 | 10400 | 15 | 188 | 909768 |

일별 수량은 0/10/20/20/10/0/0, 총자산은 1000000/994985/993971/1013971/1020768/1020551/1020551이다. 총수수료 60원·세금 389원·순손익 20551원. 매도 realized_pnl 합 20580원에는 매수 수수료 29원이 빠져 있으므로 최종 순손익과 같다고 표시하지 않는다.

## 구현·검증 계약

- CLI: `python -m examples.cpu_split_demo`; 선택 `--output-dir results/cpu-split-demo`.
- CSV: UTF-8 BOM, 날짜 ISO, 원화·수량 정수, 무작위 ID·시간 제외. trades.csv와 daily_equity.csv.
- 전일 조건→당일 시가, 최대 분할·쿨다운, 전체 입력 사전 검사, 미래 자료 불변, 후보 없음, DB/네트워크 차단, 반복·CSV·실패 종료를 새 검사로 확인한다.
- 기존 CPU 34개와 예제, 관련 CPU 18개, 새 예제 검사, 실행기 자체 22+2개. DB 3개·연결 제한 14개·Secret Scan·Docs preview 유지.
- 실행기의 예제 인수 격리/복구와 기존 비정상 종료 보고서 자료를 보완한다.
- mysql-connector-python 26.10.0과 tqdm 4.67.1을 고정 추가하고 CI 환경 기록에 포함한다. 사용자 PC에 환경을 설치하지 않고 무료 GitHub ubuntu-24.04/Python 3.12에서 실제 검사한다.
- sol_reviewer(gpt-6.1-sol/xhigh)의 읽기 전용 연결 지점·최종 후보 검토를 통과한다. 계획 검토의 인수 유입·일별 수량 출처·마지막 날 누락 지적을 반영한다.
- 제품 결함이면 범위 밖 수정이나 기대값 완화 없이 원인·재개 조건을 남긴다. 설치 장애는 근거를 확인해 같은 SHA로 한 번 재시도하고 실패를 무시해 병합하지 않는다.

## 진행과 다음 행동

별도 작업 브랜치에서 구현을 시작했다. 최종 후보 SHA·실제 검사 수·리뷰·PR·병합 후 CI와 Pages 결과는 확인 후 아래에 기록한다. 합격 후 문서에 CPU 재현 단계 완료를 표시하고 이 문서를 done_으로 전환하며, 이번 작업 브랜치만 정리한다.

- 구현 연결 지점의 sol_reviewer(gpt-6.1-sol/xhigh) 읽기 전용 리뷰: 차단 지적 없음. 실제 실행 통과는 별도 확인해야 한다.
- 로컬에서는 AST 문법·diff·문서 링크만 확인한다. 네 제품 CPU 파일은 docstring을 제외한 AST가 기준 main과 같음을 확인했다. 제품 계산을 로컬에서 시험하거나 새 환경을 설치하지 않았다.
- 현재 검사 구성: 기존 CPU 52개+새 예제 20개=72개, 실행기 자체 24개. 실제 실행 결과로 확정할 예정이며 아직 통과 기록이 아니다.

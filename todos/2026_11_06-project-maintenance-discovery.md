## 1. 결론과 판단 원칙

정비의 우선순위는 **완료·미완료 상태 맞추기 → 근거로 이동하는 경로 개선 → 작은 화면·문서 사이트 정돈 → 별도 기술 부채 해결**이다. 기존 README와 세 구현 사례, 실패한 실험·원복 기록, 외부 연결 없는 검사 경로는 유지할 강점이다.

이슈가 적거나 문서 이름에 `done_`이 많다고 역량이 증명되는 것은 아니다. 이 저장소에서는 **무엇을 끝냈고, 무엇을 검증하지 못했으며, 왜 특정 선택을 했는지**를 코드·검사·PR에 연결하는 정비가 가장 직접적이다. 실제 채용 평가나 선호를 측정한 결과는 아니며, 방문 동선에 근거한 편집 판단이다.

- 기존 대표 저장소와 개발 이력 유지. 새 포트폴리오 저장소·자기소개서·면접 준비로 과제를 바꾸지 않는다.
- 기관 운영 경력·실전 투자 성과·현재 서비스 운영 여부를 추정하지 않는다.
- 사용자 확인 범위인 개인 프로젝트 설계·구현·테스트·운영 주도 표기는 유지한다.
- Bio는 이미 확정한 **“AIOps와 운영 자동화에 관심이 있습니다.”** 문구만 준비한다. 계정 적용은 기존 합의대로 제외한다.
- 과거 로그·실패 실험·연구 제안은 지우지 않는다. 현재 안내와 당시 기록을 구분한다.
- 모든 원제안을 아래 원장에 보존했다. 중복 제안은 연결하고, 선택·보류·제외·오탐도 삭제하지 않았다.

PR #109/#110 본문은 기존 `main/todos/...` URL을 직접 참조한다. **파일 이름·내부 참조·외부 PR 링크를 한 묶음으로 정비**해야 한다. 외부 참조를 바꿀 수 없다면 기존 경로의 짧은 이동 안내 또는 파일명 유지+명확한 상태 머리말을 적용한다. 링크를 깨뜨리면서 파일 수만 줄이지 않는다. 과거 커밋에 고정된 증거 링크는 보존한다.

### #59 재숙의 결론

두 관점 모두 동일 문서를 부분 완료로 정정하고 `done_`를 제거하는 안을 권고했다. 원래 완료 기준을 나중에 “무DB 환경에서 가져오기·skip 확인”으로 축소하면 약속 자체를 바꾸게 되기 때문이다.

- 완료된 범위: 당시 Strategy/Execution 인터페이스 정비와 환경 부재 시의 가져오기·건너뜀 처리.
- 미완료: 실제 MySQL 통합 실행·통과.
- 확인된 현재 문제: [검사의 인자 전달](https://github.com/Lee-Ju-Yeong/Split_Investment_Strategy_Optimizer/blob/cf9af35b0f3038506a7f574a68565df559df0f02/tests/test_integration.py#L57)과 [무인자 DB 함수](https://github.com/Lee-Ju-Yeong/Split_Investment_Strategy_Optimizer/blob/cf9af35b0f3038506a7f574a68565df559df0f02/src/db_setup.py#L5)가 불일치하고 예외가 SkipTest로 바뀐다.
- 가장 강한 반대 근거: 옛 외부 링크가 끊기거나 이미 반영된 수정까지 미완료로 보일 수 있다. 완료 구현과 미완료 검증을 분리 표기하고 참조를 보존한다.
- 결론 변경 조건: 당시 단계 분리·범위 축소에 대한 명시적 합의 및 남은 조건 이관 기록이 발견될 때. 단순 병합 사실은 충분하지 않다.
- 경로를 안전하게 바꿀 수 없으면 기존 이름을 유지하되 **“이 문서는 #59 전체 완료를 뜻하지 않는다”**는 머리말을 둔다. 별도 미완료 문서만 만들어 오해를 남기는 방식은 권하지 않는다.

**담당:** 실제 후속 실행은 메인 Codex가 수행하고, 공개·계정·제품 정책의 결정권자는 저장소 소유자다. 이번 두 서브에이전트는 탐색만 수행했다. 아직 제품 수정 담당이나 운영 재개를 확정한 것은 아니다.

검증을 변경 성격에 맞춘다.

- 문서·경로 변경: 변경 diff, Markdown 링크·앵커, GitHub와 Pages의 실제 주소, 이동 전 도구/명령 참조, 심볼릭 링크를 확인한다.
- 현재 CPU checks는 경로 필터가 없어 문서 PR에도 자동 실행된다. 그 결과와 Secret Scan·Pages를 확인하되 문서 정비 때문에 GPU·DB 전체 검사를 별도 반복하지 않는다.
- 실행 코드·테스트·의존성·CI 동작이 바뀌는 후속 과제는 해당 검사와 실패 전파를 다시 검증한다. 기존 최소 검사 34개를 전체 제품 검증으로 확대하지 않는다.
- 보안·데이터 정합성·금융 계산에 영향을 주는 후속 제품 수정은 별도 계획과 지정 리뷰를 적용한다.
- 운영 데이터 변경, 원격 브랜치 일괄 삭제, 이력 재작성, 저장소 공개 범위·보호 설정 변경은 이 정비안의 기본 실행 범위가 아니다.

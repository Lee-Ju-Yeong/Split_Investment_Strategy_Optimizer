## 결론

- 기존 수집기는 **종목마다** 호출한다. 표 5개 하루치 갱신에 KRX 약 13,867회, 네이버 약 2,773회가 든다(종목 2,773개 기준).
- 새 경로는 **거래일마다** 전 종목을 한 번에 받는다. 거래일 하루에 KRX 12회, 외부 조회가 있는 실행마다 로그인 3회(중복 로그인이면 4회).

## 원본과 사본

- `--expect-database`는 필수다. 연결된 DB 이름(`SELECT DATABASE()`)이 다르면 아무것도 하지 않는다.
- 원본(`stocks`)에 쓰는 실행은 `--write-floor`가 필수이고 `20260209`보다 이른 값은 거부한다. 이렇게 하면 공매도 2/4~2/6(표 MAX 02-03 이후지만 사본 전용 경계 입력)이 원본에 들어가지 않는다. 하한이 표 MAX보다 뒤라 사이 거래일이 비게 되면 멈춘다.
- 그 결과 원본에서는 2/9~2/11 Tier에 필요한 공매도 원천일(2/4~2/6)이 없어 Tier 단계가 멈춘다. Tier는 2/4~2/6을 받은 **사본**에서 계산하고 검증한 새 키만 원본에 옮긴다(복구 계획 합의).

## 로그인 정보·잠금·DB 연결

- KRX 자격은 `$R/secrets/krx.env`(소유자 전용 600)에 `KRX_LOGIN_ID=...`, `KRX_LOGIN_PW=...` 두 줄. `--credentials-file` 또는 `KRX_CREDENTIALS_FILE`로 넘긴다. 그룹·기타 사용자에게 열린 파일은 거부한다.
- 자격 값·쿠키·응답 본문·서버 오류 문자열은 출력하지 않는다. 오류는 고정 분류명(예: `login_rejected`, `blocked_http_403_event_2`, `unexpected:KeyError`)과 정수 HTTP 상태만 남긴다.
- 실행 간 단일 잠금 파일(기본 `/tmp/split-krx-session.lock`, `--lock-file`로 변경)을 잡는다. 다른 실행이 잡고 있으면 로그인 전에 멈춘다.
- DB는 실행 디렉터리의 `config.ini`(`src.db_setup.get_db_connection`)를 쓴다. 이 경로는 `create_tables()`를 부르지 않는다.

## v3에서 바뀐 동작

- `--dry-run`과 `--verify-date`를 함께 주면 세션·DB를 열기 전에 사용 오류(종료 코드 3)로 끝난다. 대조는 기준일 저장 자료·DB 이름·예산(15)을 로그인 **전에** 확인한다.
- `--max-dates N`은 일반 수집·공매도·지표·Tier 각 단계의 실제 대상 날짜에 각각 적용된다(계획의 `step_through`).
- 응답: 투자자 네 주체 어디에도 없는 명단 종목·'-'만 있는 종목은 `--max-unobserved-investor`(기본 0)를 넘으면 멈춘다. 숫자 손상은 누락과 구분해 즉시 멈춘다. 시세 '-'·공란만으로는 휴장으로 보지 않는다. 전일대비 '-'는 0으로 바꾸지 않아 그 종목은 수정주가 격리된다.
- 격리 원시 시세·사유(`quarantine-날짜.csv`)와 예정 건수(`*.pending.json`)를 DB 커밋 **전에** 쓴다. 그 기록이 실패하면 커밋하지 않는다. 커밋 후 완료 파일(`day-날짜.json`)을 쓴다. 둘 사이에서 멈췄다면 다음 실행에 `--previous-report-dir 이전폴더`를 주면 DB로 판정해 보고한다(부분 커밋이면 멈춤).
- Tier 저장 전 날짜별로 명단·가격 키·공매도 원천일 유효 키·산출 키를 대조한다(`tier-audit.json`). 계산 누락, 가격 없는 산출, 명단에 있는데 가격이 없는 종목(격리 등), 공매도 원천일 유효 행 누락이 있으면 그 날짜부터 저장하지 않고 멈춘다. 격리 종목을 알고도 저장하려면 `--tier-allow-quarantined`(사본 진단용).
- 15회 대조는 양쪽 NULL을 일치로 보고, BIGINT를 정수 그대로, FLOAT를 `CAST AS DOUBLE`로 읽어 비교한다. 수정주가는 전체·검사·격리 건수와 사유를 보고하고, 격리가 하나라도 있으면 전체 합격이 아니다.

## 절차

```bash
R=<연구 작업 기준 경로>   # 인계 문서의 R
PY=$R/env/bin/python
export PYTHONPATH=$R/repo
cd <config.ini가 있는 비공개 작업 폴더>
OUT=$R/runs/<새 실행 폴더>   # 실행마다 새 폴더. 비어 있지 않으면 거부한다
```

0. **보호 기록**: 인계 문서 3절대로 수집 전 압축 덤프와 표별 CHECKSUM을 `$R/transfer/`에 남긴다.
1. **dry-run(외부 호출 0)**: `$PY -B -m src.pipeline.krx_daily_bulk --end-date 20261120 --expect-database stocks_stage --run-tier --dry-run --report-dir $OUT/dryrun`
2. **Tier 재계산 대조(외부 호출 0, 쓰기 0)**: 이미 저장된 1/5~2/6을 메모리에서 다시 계산해 `computed_at` 외 모든 열을 원본과 비교한다(FLOAT는 DOUBLE로 읽음).
   - 저장 당시 방식 재현: `$PY -B -m src.pipeline.krx_daily_bulk_tier --start 20260105 --end 20260206 --expect-database stocks --reproduce-march14 --report-dir $OUT/tier-repro` — 2026-03-14 `tier_backfill_window --start-date 20170418 --chunk-days 365`의 마지막 묶음(2025-04-16~2026-02-06, mode=backfill, 기본 인자)을 그대로 돌리고 평가 구간만 비교한다. `mismatch_rows.csv`에 다른 행이 남는다.
   - 새 경로 입력: 같은 명령에서 `--reproduce-march14` 대신 옵션 없이(구간 전 종목·1,300거래일 이력) 또는 `--legacy-inputs`.
   - 무거운 계산이다(20분 이상, 메모리 수 GB). `nice`로, 한 번에 하나만 돌린다. 일치면 0, 차이 있으면 4.
3. **15회 대조(쓰기 0, KRX 정확히 15회 예산)**: 2026-02-02를 다시 받아 기존 결과와 비교한다(명단·시장, 원시·수정 OHLC, 시총, 재무, 투자자, 공매도).
   `$PY -B -m src.pipeline.krx_daily_bulk --expect-database stocks_stage --verify-date --credentials-file $R/secrets/krx.env --report-dir $OUT/verify`
   - BIGINT는 정수로 정확히, 가격은 저장 소수 자릿수로, 재무 FLOAT는 float32 저장 정밀도로 비교한다. 하나라도 다르거나 일부 주체·미집계·누락이 있으면 종료 코드 4. 중복 로그인으로 16번째 호출이 필요하면 예산 초과(종료 코드 2)로 대조 미완료다.
4. **소량 smoke(사본)**: `--max-dates 1 --max-krx-calls 40`. 보고 폴더의 `day-*.json`, `quarantine-*.csv`, `report.json`의 `watermarks_after_db`를 본다.
5. **본 실행(사본)**: 접속이 끊겨도 이어지도록 `systemd-run`으로 띄운다. 끝나면 사본에서 검증하고, 원본에는 `--write-floor 20260209`로 검증된 새 키만 옮긴다(옮기는 절차는 원본 반영 직전 승인 지점에서 정한다).
6. **사후 확인**: 보호 구간의 행 수·내용 CRC 불변(인계 문서 3절), 새 날짜의 표별 건수, 격리 종목 목록.

평일 휴장일은 시세 호출 1회로 판별하고 나머지 호출을 건너뛴다. `--holidays-file`을 주면 그 1회도 줄인다. 이미 저장된 거래일에 휴장 응답이 오면 오류로 멈춘다.

## 차단·중단 시 대응

- 속도 제한: 동시 1개, 4초+0~2초, 40회마다 45~70초. 전송부터 응답 판정·휴식·재로그인까지 한 잠금 안에서 처리한다. 자동 리디렉션은 따라가지 않는다(3xx는 중단).
- 403·429·5xx·LOGOUT: **첫 응답에서 바로 멈춘다**(종료 코드 2, 사용자 결정 11-22, `--max-block-events` 기본 1). 2 이상을 주면 그 전까지는 10분 쉬고 다시 로그인해 한 번 재시도한다. 그 밖의 비정상 HTTP 상태, 리디렉션, 전송 오류도 첫 번째에 멈춘다.
- 로그인 전 요청도 실행 간 잠금을 먼저 잡고, 닫은 세션은 다시 전송하지 않는다.
- 한 번 멈춘 세션은 이후 모든 전송을 네트워크에 보내지 않고 거부한다(예외를 삼키는 옛 수집기가 같은 세션을 써도 다시 두드리지 않음).
- 예산(`--max-krx-calls`)을 넘기려 하면 보내기 전에 멈춘다(종료 코드 2). 응답 불완전·새 키 규칙 위반은 종료 코드 3, 대조 불일치는 4, 예상 밖 오류는 1.
- 날짜 하나가 실패하면 그 날짜의 모든 표를 롤백한다. 이미 커밋된 날짜는 날짜별 증거 파일이 있다. 다시 실행하면 표별 보호 상한 다음 날부터 이어서 받는다.
- 차단으로 멈추면 그날은 다시 시도하지 않는다. `docs/operations/krx_hotspot_db_tunnel_runbook.md`의 네트워크 판별부터 한다.

## 남은 위험

- 날짜별 응답이 기존 종목별 결과와 같은지는 실제 응답으로 확인하지 않았다(3단계가 첫 근거). 특히 투자자 순매수 목록의 전 종목 포함, 공매도 잔고표와 종합정보 잔고금액의 날짜 기준.
- 수정주가는 비율 1 종목만 이어 쓴다. 비율≠1·사건·신규 상장 종목은 매일 격리되며, 이 종목들의 주가·Tier는 별도 승인된 수정계열 처리 전까지 원본에 없다.
- 종목 명단이 주 1회에서 거래일마다로 바뀐다.

# ETF M2 기준 엔진 사용과 검증 범위

M2는 실제 제품 V2 매매 결정을 두 일봉 경로로 근사하는 Python 기준 엔진이다. 수익성 평가나
자동매매 프로그램이 아니다. 구현·검증·검토 상태는 [진행 기록](../../todos/2026_11_17-etf-m2-engine.md)을 따른다.

## 작은 예제로 확인

```powershell
python -m examples.etf_m2_demo
python tools/ci/run_cpu_checks.py
```

예제는 가상 국내 ETF에 1차 10주를 1,000원에 사고 다음 날 1,100원에 판 뒤, 셋째 날 900원이어도
1차를 다시 사지 않는 사례다. 수수료는 명시적으로 0이고 초기 현금은 100,000원이다.
두 경로 모두 매수·매도 2건, 최종 현금 101,000원, 잔여 보유 0으로 검산한다.
실제 과거 투자 성과나 실제 증권사의 비용 청구 결과를 나타내지 않는다.

2026-11-17 Opus 1차 검토 전 후보는 Ubuntu WSL Python 3.12.3과 고정 의존성에서 CPU 442개·예제 3개·
실행기 자체 24개를 통과했다. GitHub 원격 CI나 GPU/DB 전체 검증 결과는 아니다. Windows의 선행
CPU 검사는 통과했으나 실행기 자체의 자식 프로세스 취소/SIGTERM 검사는 실패했다. 이 Windows
실행기 호환성 한계는 매매 엔진 검사 통과와 구분하며 원래 Linux CI 명령을 최종 검증에 사용했다.
이후 Opus가 미체결 주문 교체·환전 기준 혼합을 발견해 수정했고, 최종 후보는 CPU480개·예제3개를
통과했다. 동일 소스 실행기의 자체24개 통과 증거는 재사용했다. Opus r3는 M2 기준 엔진을 M3 대조에
쓰는 범위에 남은 차단이 없다고 확인했다. 실제 세후·실전·수익성 승인과는 구분한다.

## 엔진 입력과 결과

`src.research.etf.engine.run_engine`에 상품, 시각이 붙은 일봉, 차수 규칙과 통화별 초기 현금을 넘긴다.
모든 금액·비율은 Decimal, 시각은 시간대가 있는 datetime이다. 비율 5%는 `Decimal('.05')`다.
첫 차수 수동 진입은 최초 거래일 한 번이고 이후 재진입하지 않는다. 현금이 부족하면 주문을 거절하며
주문 수량을 줄이지 않는다. 매수 예산 안에서 정수 수량을 계산하는 것과 현금 부족 거절은 별개다.

반환 `EngineResult`의 trades는 체결, rejections는 거절, valuations는 알려진 가격·환율로 계산한
평가, cash_events는 환전·결제·배당 등의 사건이다. final_cash와 positions는 마지막 처리 사건의 상태다.
세금 기록의 `actual_after_tax_approved`는 false이며 실제 세후 승인을 뜻하지 않는다.

`equity_krw`는 확정 미납만 차감한 장부 평가다. `estimated_tax_krw`와
`equity_after_estimated_tax_krw`는 진행연도에 이미 실현한 손익에서 알려진 추정세를 반영한 보고값이다.
후자는 세무 계산기의 보조 진단값이며, 설계 3.9의 전량 청산 가정 세후 곡선이 아니다. 설계의 주곡선은
현재 연도 추정세를 빼지 않는 장부 곡선이다. 월 차수 예산·한도도 장부 평가를 쓰며 현재 연도 추정세를
주문 판단에 넣지 않는다. 미래 손익이나 연말 확정값을 미리 쓰지 않는다.
확정 미납의 회계상 차감과 실제 현금을 준비금으로 묶는 동작은 별개다. 현재 엔진에는 준비금에 따른
매수 차단, 납부 부족 시 환전·강제매도, 종료 전량 청산세·청산 가정 곡선이 없다. 세금 설계 3.10의
사례7·8은 후속 필수 작업이며 완결된 합성 세후 성과 보고나 실제 세후 판정을 승인하지 않는다.

장중 O-H-L-C/O-L-H-C의 고가·저가는 세션 1/3·2/3 시각에 있다고 가정하고 구간을 선형으로 잇는다.
이 시각은 실제 장중 체결 관측값이 아니다. 두 경로를 각각 실행해야 하며 결과를 보고 하나를 고르지 않는다.
매도 수익률 판단은 원금 분모·비용 차감·0.01% HALF_UP, 여러 차수의 익절 순서는 제품 SHA256 순서다.
조건이 처음 성립한 주문 한 건을 고정하며, 관통이 부족해 미체결이어도 그날 다른 주문으로 바꾸지 않는다.
당일 끝까지 미체결이면 다음 거래일에 다시 판단한다. 처음 시가 진입이 불가한 상품도 이후 자동 재진입하지 않되
`first_entry_unavailable` 사유와 경고를 남긴다.
[고정 제품·손계산 사례](etf_m2_product_cases.md), [호가·비용의 공식 근거와 제한](etf_execution_rules.md)을 함께 읽는다.

기존 ChatGPT `shared_account.cpp`와는 공통 규칙의 합성3사례(추가 매수 후 단일 차수 매도,
1차 매수·매도, 공유 현금 부족 거절)에서 거래6행·일별 평가6행과 비용·현금을 대조해 일치했다.
비용0·정수 수량·같은 고정 예산·양쪽에서 조건을 만족하는 갭 주문으로 제한한 비교다. 전일 종가 신호와
장중 경로, 1차 재진입, 동시 복수 매도, 세금·환전·기업행사처럼 다른 규칙의 전체 동등성을 뜻하지 않는다.

## 고정 M1 자료 연결

`src.research.etf.engine_inputs.load_m1_inputs(data_root, symbols, start, end, split_csv)`는
명시한 탐색 상품만 입력으로 준비한다. 보류 상품은 가격을 읽기 전에 거부한다. 금은 원래 분할의 both를 허용한다.
시작 전 3년 이력·직전 20거래일 거래대금·상품 유형을 확인하며, 분할·분류표·가격 묶음 해시가 바뀌면 실패한다.
기존 분할을 재생성하거나 M1 원본에 쓰지 않는다.

요청 종료일은 사용하는 시장의 저장 달력 확인 범위 안이어야 한다. US 상품은 환전 일정에 필요한
국내 달력과 NYSE 달력 모두를 확인하며, 범위를 넘는 기간을 짧게 잘라 실행하지 않는다.

요청 기간 마지막 실제 시장 세션까지 가격이 있어야 한다. 상장폐지·거래정지·말미 자료 누락이면
자동 청산을 추정하거나 마지막 가격으로 보유를 동결하지 않고 실패한다. 상장폐지 청산 사건 지원은
현재 연결부에 없으며 그 기간이 포함된 상품을 탐색에 쓰기 전에 구현해야 한다. 거래량0/OHLC0 자료도
상품·날짜·원본 ohlc_ok가 붙은 오류로 거부하고 직전 가격으로 자동 보정하지 않는다.

반환 입력의 `engine_kwargs()`에는 공표 시각이 붙은 환율, 한국시간 18:00 평가, 10:00 환전 일정,
US 실제 거래 세션과 결제 가용 시각이 들어 있다. 결제 가용 시각은 M1 NYSE 마감 시각을 보수적으로
사용한 연구 가정이며 실제 증권사의 결제 완료를 관측한 값이 아니다. 마지막 US 종가가 알려진 뒤
18:00 종료 평가를 한 번 추가한다. final_cash는 이 평가와 별개로 나중 결제 사건까지 포함할 수 있다.

상품의 과거 가격이 한 가격으로 고정된 날은 제한폭에 묶였는지 자료만으로 판단할 수 없다.
이때 `locked_status[(symbol,date)]`에 확인한 bool이 없으면 실행하지 않는다. 지급일은
`payment_dates[(symbol,date)]`에 확인한 시각만 넣는다. 지급일 없는 미국 분배금은 미수금으로
평가하되 현금으로 재투자하거나 환전할 수 없다. 국내 휴장일에 시작하는 US 초기 환전 정의는 미확정이므로
현재 연결부는 그 경우를 거부한다. 이 선택은 M5 시작일 설계에서 다시 검토할 수 있다.

프로토콜은 `1.1.2-m2-draft`, M2 시장 규칙은 파일 해시로 연결된다. M1 분할의 원래
`75ac3889ccb2...` 해시는 생성 기록에 그대로 남으며, 실행 설정 해시와 구분해 provenance에 기록한다.
호가·SEC 수수료 표의 확인 범위 밖은 0이나 마지막 요율로 대체하지 않는다. US 신호에 전달하는 SEC
요율은 검증한 결제일과 거래 당시 공표 정보로 정한다. 명시한 합성 override만 이를 우회한다.

## 남은 제한과 다음 단계

- 실제 자료의 세후 판정은 보류한다. after_tax는 완전한 합성 자료의 `synthetic_tax_data=True`만 허용한다.
  국내 기타 ETF 과표기준가·분배 이월·법적 형태·외국납부세액·종합과세·납기 휴일 조정에는 제한이 있다.
- raw 가격 주식분할은 세무 원가 원장과 함께 조정하는 API가 없어 거부한다. Yahoo 분할반영 시세의
  split_ratio를 수량에 다시 적용하지 않는다. 국내 Naver 가격은 분배금 반영 미확인 수정가격이라 호가도 가상 근사다.
- 배당락 직전 전략 보유와 결제 세무 보유가 다르면 세전 자체 미수만 기록하고 세후 실행은 거부한다.
- KR 매도 대금은 즉시 재사용·환전 가능 현금으로 근사한다. 실제 T+2 결제와 같지 않으며 M5 실제
  혼합시장 탐색 전에 모델을 재검토해야 한다([KRX ETF 결제제도](https://regulation.krx.co.kr/contents/RGL/03/03060102/RGL03060102.jsp), 2026-11-17 확인).
  US 세무 귀속연도·환율은 명시한 결제 가용시각의 KST 날짜와
  그 시각까지 공표된 MAR를 쓴다. 미국 결제일의 KST MAR나 실제 신고 금액을 재현한 것으로 주장하지 않는다.
- `LevelRule.take_rate`는 0 이상이다(제품은 -2%까지 허용). 제품 설정의 `validate_drops`가 요구하는
  왕복 비용 이상 하락률을 엔진에서 강제하지 않는다. 손계산의 개별 결정과 유효한 공통 설정 대조 범위다.
  M5 탐색 설정을 실제 제품 설정으로 연결할 때 이 유효성 조건을 별도로 충족해야 한다.
- `run_engine`을 연결부 없이 직접 호출할 때는 호출자가 의도한 전체 기간·실제 세션·가격 완전성을
  먼저 검증해야 한다. M3/M4도 strict M1 연결부 또는 동등한 검사를 거친 입력만 사용한다.
  마지막 Bar를 의도한 종료일로 추정하거나 누락을 보유 가격 동결로 해석해서는 안 된다.
- Decimal 기준 엔진은 정확성 검산용이며 호가 전수 순회가 있어 빠르지 않다. M3에서 빠른 커널을 만들고
  이 기준 엔진과 대조한다. M4 기준선, M5 탐색, M6 고정, M7 보류 평가와 M8 전진 검증은 이후 작업이다.

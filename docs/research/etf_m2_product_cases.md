# ETF M2 독립 제품 사례와 손계산 기대값

이 문서는 엔진 구현을 읽기 전에 고정한 합성 사례의 계산 근거다. 실제 시세·계정·DB를 사용하지 않는다.
수치 원본은 [etf_m2_cases.json](../../tests/fixtures/etf_m2_cases.json), 실행 검사는
[test_research_etf_engine_contract.py](../../tests/test_research_etf_engine_contract.py)다.
기대값은 JSON의 십진 문자열·정수·시각이며 검사 중 다른 엔진이나 모의 엔진으로 다시 계산하지 않는다.

## 고정 제품 근거와 적용 범위

`git -C D:/leerj/Projects/split-trader show aaa3bb9:<path>`로 다음 세 파일만 읽었다.
인접 저장소 파일을 import·실행하거나 수정하지 않았다.

| 고정 커밋 경로 | 확인한 함수와 의미 |
| --- | --- |
| `back/src/split_trader/kiwoom_integration/product_trading_policy.py` | `decide`: 매도 우선, 2..N 중 가장 낮은 빈칸만 선택, 바로 전 번호가 없으면 중단. `price_drop_met`: 수수료를 제외한 원금/수량으로 정확히 비교. `sale_candidates`: 시장가·보정 지정가의 순수익률을 모두 확인하고 SHA256 순서로 선택. |
| `back/src/split_trader/accounting.py` | `valuation`: 매도대금−원금−매수수수료−매도수수료−매도세금. 분모는 수수료 제외 원금. `decision_return`·`round_away`: 0.01% 단위, 중간값은 0에서 멀어지는 방향. `maximum_quantity`: 예산으로 최대 정수 수량을 먼저 결정하고 현금 부족은 별도로 거절. |
| `back/src/split_trader/amounts.py` | `Q8=100000000`, 정확한 십진 문자열 파싱과 정수 금액. 기대값을 이진 부동소수점으로 만들지 않을 근거. |

**세 정책을 구분한다.** 프로젝트 CPU의 `fixed_slot_v1`은 1차가 빈 보유 종목도 신규 진입 조건이 맞으면
1차를 다시 채운다(`todos/2026_11_15-fixed-split-slot-v1.md`). 고정 제품 V2의 `decide`는 자동 추가 매수
차수를 2부터 찾으므로 1차를 자동 재진입하지 않는다. 연구 M2는 각 상품 최초 시가에서 수동 1차 진입을
한 번 제공하고 이후에는 제품 V2처럼 1차를 자동으로 채우지 않는다. CPU 정책의 1차 재진입을 M2에
그대로 적용하면 `no_first_level_reentry`가 실패해야 한다. 제품의 수동 주문 등 별도 경로 전체를
조사한 것으로 확대하지 않는다.

M2의 시장별 비례 수수료와 제품의 10원 단위 절사 수수료는 다르다. 제품 기본 비용표의 주식 세금도
ETF 기본 비용과 다르다. 따라서 비용을 0으로 명시한 합성 사례로 차수·비교·반올림을 분리해서 검산하고,
별도 비용 사례에서는 연구 수수료를 적용한다. 제품 실행 결과와 완전 일치한다는 주장은 하지 않는다.
미국 단독 전략 사례는 SEC 날짜 규칙과 섞이지 않게 `sec_rate_override=0`을 명시한다.

## 차수·원가·매도 순서

별도 표시가 없으면 예산 1,000, 추가 하락률 10%, 보유 원가 100, 시가 90, 수수료 0이다.

| JSON 사례 | 독립 기대값과 이유 |
| --- | --- |
| `empty_has_no_automatic_first_entry` | 자동 첫 진입을 끈 빈 포트폴리오에는 주문 없음. |
| `missing_first_but_second_anchors_third` | 2차만 보유하면 가장 낮은 빈칸은 3차. 2차 원가 100의 90%인 90에 11주, 990 지출. 1차가 없다는 이유로 전체 추가 매수를 막으면 실패. |
| `missing_first_and_second_blocks_later_levels` | 3차만 보유하면 대상은 2차지만 기준이 될 1차가 없으므로 주문 없음. 4차로 건너뛰지 않음. |
| `middle_hole_uses_previous_number_not_latest` | 1차 100·3차 50 보유 시 2차의 기준은 1차 100. 90에 11주. 가장 최근 차수 50을 기준으로 삼으면 실패. |
| `all_levels_occupied` | 1..4차가 모두 차 있으면 추가 매수 없음. |
| `buy_fee_is_not_part_of_drop_anchor_reject` | 2주×100.05=원금 200.10. 10% 하락 경계는 90.045. 90.05는 경계보다 높아 주문 없음. 매수수수료 100을 원가에 더하면 잘못 매수하게 됨. |
| `exact_principal_drop_accept` | 같은 원가에서 90.04는 경계 아래. 11주 대금 990.44는 1,000 이내, 12주는 1,080.48로 초과. |
| `sha256_order_*` | 고정 해시 순서는 1→4→3→2. 보유 후보 2·3·4 중 4차를 매도. 3차의 수익률이 가장 높고 2차의 번호가 가장 작아도 선택은 4차. 입력 목록 순서를 바꿔도 동일. |
| `sell_wins_when_buy_and_sell_are_simultaneously_eligible` | 1차 원가 100을 기준으로 2차 매수 경계가 90인 동시에, 3차 원가 50·목표 10%의 매도 조건도 시가 90에서 성립. 매수 대신 3차 10주 매도. |

해시 원문과 64자리 16진수는 JSON에 함께 저장했다. SHA256 표준 함수로 `ETF:1`부터 `ETF:4`까지
문자열을 한 번 계산해 고정했으며, 실행 중 기대 매도 차수를 정렬해서 만들지 않는다.

## 비용과 0.01% 반올림 경계

`fee_inclusive_integer_quantity`: 예산 100,000, 가격 10,000, 연구 수수료율 0.00015.
10주 대금 100,000 + 수수료 15 = 100,015로 예산 초과다. 9주는 대금 90,000 + 13.5 = 90,013.5로
가능하므로 기대 수량은 **9주**다. 제품의 10원 절사라면 수수료는 각각 10·10이지만 이 사례의 정수
수량은 여전히 9주다. 두 체계의 수수료 금액 자체를 같다고 검사하지 않는다.

`return_half_up_*`: 원금 1,000주×200 = 200,000, 매도대금 1,000주×210 = 210,000, 매도비용 0,
목표 5%=비율 0.05. 순수익률은 `(10,000−매수수수료)/200,000×100`이다.

| 매수수수료 | 정확한 백분율 수익률 | 0.01% HALF_UP | 주문 |
| --- | --- | --- | --- |
| 10 | 4.995% | 5.00% | 1차 1,000주 매도 |
| 10.00000001 | 4.994999999995% | 4.99% | 없음 |
| 9.99999999 | 4.995000000005% | 5.00% | 1차 1,000주 매도 |

기대값을 엔진 수익률 함수를 호출해서 만들지 않는다. 1e-8 통화 단위의 차이는 제품 q8 정밀도 안이며,
첫 두 행은 반올림 전 목표 비교가 들어가는 회귀를 구분한다. 별도 `return_half_up_differs_from_half_even`은
매수수수료 30일 때 `(10,000−30)/200,000×100=4.985%`, 목표 4.99%를 쓴다. HALF_UP은 4.99%로
매도하지만 HALF_EVEN은 4.98%로 매도하지 않아 두 반올림 방식을 구분한다.

## 두 장중 경로·갭·관통·거래 금지일

합성 세션은 13:30~19:30 UTC의 6시간이다. 꼭짓점은 15:30·17:30 UTC다. 실제 미국 거래시간을
재현하는 달력이 아니라 시각 산술을 명확히 만드는 합성 입력이다. 미국 호가 0.01, 관통 1호가를 쓴다.

원가 100·목표 10%인 1차와 2차 매수 경계 90에 O=100, H=120, L=80, C=100을 넣는다.
O-H-L-C는 110 지정가의 매도 가능 호가 **110.01**에 먼저 닿고, O-L-H-C는 90 지정가의 매수 가능
호가 **89.99**에 먼저 닿는다. 첫 구간 길이 7,200초×10.01/20 = **3,603.6초**이므로 둘 다
14:30:03.600000 UTC에 각각 SELL 1차 10주 / BUY 2차 11주다. 체결 가격은 관통 호가가 아닌
지정가 110 / 90이다. 하루에 하나만 선택해야 하며 나중의 다른 신호를 더 넣지 않는다.

매수 갭 시가 80이면 90 지정가 대신 80에 12주(960), 매도 갭 시가 120이면 110 대신 120에 10주다.
시가 100에서 저가 90 / 고가 110에 닿기만 하면 기본 1호가 관통 조건을 만족하지 않아 주문이 없다.
저가 89.99 / 고가 110.01까지 가면 각각 90 / 110 지정가에 체결한다. 이 사례는 해당 꼭짓점에서
처음 가능해지므로 시각도 17:30 / 15:30으로 고정했다. 거래량 0이나 `limit_locked=True`면
조건에 맞더라도 최초 진입·매도 모두 주문이 없어야 한다.

통합 검사는 실제 `run_engine`을 호출한다. 평가액 기대값을 검증하려고 시장가 조회나 원장 함수를
모의 객체로 바꾸지 않는다. 미래 결제일 환율도 거래 시각에 미리 쓰지 않는지 앞선 원장 비교로 검사한다.
결제일은 테스트가 제공한 미국 세션과 결제 시각으로 고정하며 주말·휴일을 추측하지 않는다.

이 사례는 엔진의 계약과 합성 원장 검산이며 전략 수익성, 실데이터 적합성, 실제 세후 성과 또는
실전 운용 승인을 뜻하지 않는다. 세금의 개별 독립 계산은 별도 `test_research_etf_engine_tax.py` 범위다.

## Opus 반례를 고정한 추가 계약

2026-11-17 후속 검토의 HIGH-1·HIGH-2를 구현 수정 결과를 보기 전에 추가했다. 기존 기대값은 유지한다.

**HIGH-1: 당일 첫 주문을 미체결 상태에서도 교체하지 않는다.** KR ETF, 2025-03-04,
O=10,000·H=10,500·L=9,400·C=9,600, 1차 10주 원가 10,000·목표 5%, 2차 하락률 5%,
2차 예산 100,000, 수수료 0, 관통 1호가다. KR 호가는 5다.
O-H-L-C에서는 10,500 매도 조건이 먼저 성립해 그 주문이 그날의 한 건을 차지하지만,
고가가 10,505에 이르지 않아 미체결이다. 뒤에 9,500 매수가 가능해져도 주문을 교체하지 않으므로
기대값은 **None**이다. 반대로 O-L-H-C는 첫 주문이 2차 9,500 매수이고, 9,495까지 관통하므로
**BUY 2차 10주, 지정가 9,500**이 유일한 체결이다. 합성 6시간 세션의 첫 구간 7,200초에서
505/600×7,200=6,060초이므로 체결 시각은 **01:41 UTC**다.
같은 금지 규칙의 반대 방향도 검사한다. O-L-H-C에서 L=9,500에 닿기만 해 첫 매수가 미체결이면,
뒤에 H=10,600에서 매도 관통이 가능해져도 매도로 교체하지 않아야 한다.

**HIGH-2: 직전 평가 뒤 생긴 보유분을 환전 목표에서 뺀다.** 초기 KRW 10,000,000·USD 0,
KR 1종목과 US 1종목으로 US 목표 비중은 50%, 환율 1,000, 환전 비용 0이다.
06-03 01:00 UTC 최초 환전으로 KRW 5,000,000·USD 5,000이 된다. 06-03 09:00 평가 시점에는
보유가 없어 총 평가액 10,000,000이다. 그 뒤 미국 개장에 100달러짜리 30주를 매수해 USD 현금은
2,000·미국 보유 평가액은 KRW 3,000,000이 된다. 국내 합성 봉은 거래량 0으로 매매를 막아
이 사례의 원인을 환전 계산에 한정한다.
06-04 01:00 두 번째 환전의 미국 목표 현금은 `(10,000,000×0.5−3,000,000)/1,000`
= **USD 2,000**이다. 최종 현금은 **KRW 5,000,000·USD 2,000**, 거래는 US 30주 매수 한 건이다.
직전 평가 때 보유가 없었다는 이유로 미국 목표 현금을 계속 USD 5,000으로 두고 USD 3,000을
추가 환전하면 실패다. 환율과 가격을 일정하게 두어 평가 시점 사이의 가격 변화와 구분한다.

**MEDIUM-2: 추정세를 반영한 보고용 세후 가치는 연말 확정만으로 떨어지지 않는다.**
coordinator가 확인한 필드는 `estimated_tax_krw`와 `equity_after_estimated_tax_krw`다.
장부 평가 `equity_krw`·월 예산·가용현금에는 기존 세금 문서대로 확정 미납 세액만 반영한다.
미국 ETF 100주를 100달러에 취득하고 2024-12-27에 200달러에 팔아 12-30 결제한 합성 사례에서,
환율 1,000·비용 0이면 원화 실현손익은 `(200−100)×100×1,000`=10,000,000이다.
연 공제 2,500,000 뒤 22% 세액은 **1,650,000**이며 매도 후 자산은 USD 20,000=KRW 20,000,000이다.
12-31에는 장부 평가 20,000,000·추정세 1,650,000·보고용 조정 평가 **18,350,000**,
01-01에는 장부 평가 18,350,000·미확정 추정세 0·보고용 조정 평가 **18,350,000**이어야 한다.
같은 세액이 추정에서 확정으로 이동해도 보고용 가치가 급락하거나 두 번 차감되지 않는다.
납부 전이므로 두 평가 뒤 실제 현금은 KRW 0·USD 20,000으로 그대로다.

보고용 조정 평가를 매매에 쓰지 않는 별도 사례도 고정한다. 미국의 같은 손익을 11월에 실현하고,
KRW 현금 9,999,000과 국내 보유 1주×1,000이 있으면 11-30 장부 평가 **30,000,000**,
추정세 **1,650,000**, 보고용 조정 평가 **28,350,000**이다. 12월 첫 거래일에 종목 2개·
첫 차수 비율 0.6이면 예산은 `30,000,000×0.6÷2`=**KRW 9,000,000**이다.
국내 시가 800에서 2차 **11,250주**를 사고 KRW **999,000**이 남아야 한다. 조정 평가를 예산에
쓰면 수량이 달라지고, 아직 확정되지 않은 추정세를 현금에 묶으면 주문을 잘못 거절한다.
기존 국내 1차 목표는 10, 미국 매도 목표는 0.05로 고정하며 보고 필드가 익절 설정을 바꾸지 않아야 한다.

## 검증 상태

2026-11-17 작성한 검사는 고정 전략 사례 26개와 명시적 통합 검사 11개다.
`python -B -m unittest discover -s tests -p test_research_etf_engine_contract.py -v`의 첫 실행은
`engine_market` 미생성으로 exit 1, 해당 모듈 생성 뒤 두 번째 실행은 `market_rules_v1.json`
미생성으로 exit 1이었다. 두 실행 모두 import 단계에서 막혀 계약 검사 통과를 뜻하지 않는다.
통합 결과의 `trades.side/level/quantity/price`와 `valuations.equity_krw`는 coordinator가 확인했다.
시장 규칙 모듈과 JSON 준비 뒤 같은 명령을 다시 실행해 **37개 통과, 13.997초, exit 0**을 확인했다.
고정 기대값을 구현 결과에 맞춰 바꾸지 않았고 구현 소스·모의 엔진을 기대값 생성에 사용하지 않았다.
초기 두 import 실패는 모듈 작성 대기로 분류하며, 실행된 37개 사례에서 드러난 계약 결함은 없었다.
이 결과는 해당 검사 파일의 범위이며 저장소 전체 검증이나 최종 통합 검토 통과를 뜻하지 않는다.

Opus 반례 후속 검사는 기존 37개에 전략 3개·통합 4개를 추가해 총 **44개**다. 기대값을 고정한 뒤
같은 지정 명령을 실행한 첫 결과는 **44개 중 실패 3개, 14.609초, exit 1**이었다.

| 분류 | 실제 결과와 고정 계약 |
| --- | --- |
| HIGH-1 전략·O-H-L-C | 첫 10,500 매도 미체결 뒤 BUY 2차 10주@9,500을 반환. 계약상 None이어야 하므로 실패. |
| HIGH-1 전략·O-L-H-C 반대 방향 | 첫 9,500 매수 미체결 뒤 SELL 1차 10주@10,500을 반환. 계약상 None이어야 하므로 실패. |
| HIGH-1 통합·O-H-L-C | 주문이 없어야 하지만 BUY 2차 10주@9,500이 거래 원장에 남아 실패. |
| HIGH-1·O-L-H-C 관통 | 첫 BUY 2차 10주@9,500·01:41 UTC가 그대로 체결되는 양성 사례는 통과. |
| HIGH-2 | 야간 보유 증가 뒤 추가 환전 없이 KRW 5,000,000·USD 2,000 유지, 통과. |
| MEDIUM-2 | 보고용 평가 18,350,000 연속성, 장부 20,000,000→18,350,000 확정 이동, 현금 유지가 통과. |
| 보고값의 매매 분리 | 장부 30,000,000 기준 9,000,000 예산으로 국내 11,250주 매수, 추정세 현금 선차감 없음, 통과. |

위 3개는 API 불일치나 모듈 대기가 아닌 첫 주문 유지 규칙의 실제 실패로 분류했다. 담당 구현 수정 뒤
같은 44개로 검증하며 실패를 통과로 바꾸려고 기대값을 변경하지 않는다.

이후 coordinator가 전달한 **담당 워커 B의 수정·검증 보고**에 따르면, 최초 주문을 고정하는 수정 뒤
B 소유 전략 검사 **47개**와 이 문서의 E 독립 계약 검사 **44개**가 모두 **exit 0**으로 통과했다.
B는 같은 HIGH-1 입력에서 O-H-L-C=None, O-L-H-C=BUY 2차 10주@9,500·01:41 UTC를 확인했다고
보고했다. 이는 위 최초 실행의 실패 3건이 수정본에서 해소됐다는 B의 검증 결과다.
E는 후속 작업에서 고정 fixture·기대값·검사 코드를 변경하지 않았으며, **수정본 검사를 중복 실행하지 않았다**.
E가 직접 실행한 후속 결과는 위 44개·실패 3개·exit 1 기록이고, 수정 뒤 44개·exit 0은 B의 보고로
구분한다. 최신 통합본 전체 검사와 Opus 재검토는 coordinator가 별도로 수행한다.

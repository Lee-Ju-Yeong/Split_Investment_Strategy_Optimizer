# M5 입력 준비와 작은 실행

M3·M4 고정 커밋은 `a2b101b`이다. 이번 구현은 국내 결제·명시 상폐 청산·입력 보호와 작은 실행을
연결한다. 실자료는 재택 PC에 있으며 현재 호스트에 연결되지 않았다. 합성 검증과 실제 자료 탐색은
별도로 기록한다. M5 전체 탐색·중첩 검증·PBO·M6 규칙 고정·보류 판정은 아직 수행하지 않았다.

## 결제와 상폐의 실행 조건

- `domestic_settlement="t_plus_2"`는 실제 KRX 세션 두 개 뒤, 명시한 가용 시각에 결제현금을 늘린다.
  매도 대금은 같은 통화의 매수에 재사용할 수 있지만 결제 전에는 환전·명시 세금 납부에 쓸 수 없다.
  매수로 이미 쓴 미결제 대금은 결제 때 다시 현금에 더하지 않는다.
- M1 연결부의 가용 시각은 결제 세션 `close_utc`를 쓰는 보수적 연구 가정이다. 실제 증권사의
  입출금 가능 시각을 관측한 값이 아니다. 기존 호출의 기본값 `legacy_same_day`는 유지한다.
  금은 기존 즉시 결제 근사이며 실제 금시장 결제시각을 구현한 것으로 해석하지 않는다.
- 국내 T+2와 `after_tax`의 결합은 결제일 원천징수 구현 전까지 거부한다. 현재 실행은 세전 전용이며
  국내 수정가격의 분배금 반영 미확인·미국 상폐 자료 부재 등 기존 한계도 유지한다.
- `DelistingEvent`는 국내 상품 코드, 공지 `known_at`, 마지막 정상 세션, 폐지일, 근거 SHA256을 받는다.
  공지는 마지막 세션 개장 전까지 알려져야 한다. 마지막 가격 행이나 월말 상장 목록만으로 추정하지 않는다.
  마지막 정상 세션의 일반 주문은 억제하고 종가에 전 보유를 한 주문으로 청산한다.
  요청 기간에 그 뒤 정상 가격행이 있으면 공지와 모순되므로 거부한다. 원본의 명시 폐지일에만 있는
  open/high/low/volume=0·close>0 표시행은 정상 일봉으로 만들지 않는다. 중복 행은 표시행도 거부한다.
  비용·불리한 슬리피지·참여율을 적용한다. 실패하면 해당 시험을 실패로 남기고 상품을 제외하지 않는다.
- 같은 시각에는 강제 청산(우선순위35)을 일반 매도/매수(40/50)보다 먼저 처리해 그 대금의 재사용을
  허용한다. 일반 주문끼리의 기존 순서는 유지한다. 실제 해지 상환금 모형은 아니다.

## 성과 전에 지정한 조건

[m5_search_v1.json](../../src/research/etf/m5_search_v1.json)에 시장별 개수·k=2/3/4/5,
바깥 학습3년/평가1년·안쪽 학습2년/평가1년·주 기준선 학습2년을 지정했다.
격자는 kg·kp 각각1/2/3, L=3/5, 첫 차수 총예산 비율0.05/0.10, 종목 상한0.5/1,
현금 하한0/0.1의144개다. 상품별 계수는 두지 않는다.
프로토콜은 설정 파일의 해시와 시장 구성·평가 기간·환율 제한을 대조한다. 여전히 `draft`다.
M1 분할의 과거 프로토콜 해시는 다시 만들지 않고 현재 실행 해시와 함께 남긴다.

작은 실행은 미리 지정한 두 설정×두 장중 경로만 모두 실행한다. 확인된1배 상품으로 만든 명시 바스켓이
필요하며 원본 `explore`와 중복 없는 고정 지수 묶음을 검사한다. 2020-01-02~2021-12-31 전략의 평균
투자 비중으로 주 기준선을 고정하고, 2022-01-03~2022-12-30에 전략과 같은 바스켓의 기준선7개를
비교한다. 평가 시점 변동성은 평가 시작 전에 다시 추정하며 공통 kg/kp는 바꾸지 않는다.
학습·평가 창은 모두 최초 환전·시장 개장 중 빠른 시각부터 시작한다. 미국 단독 바스켓의 개장 전
18KST 평가도 초기 미투자 상태로 학습 평균에 포함한다.
최적 설정을 고르지 않고, 정식 중첩 검증이나 통계적 성공으로 세지 않는다.

변동성은 자기 시장의 시작 직전251세션 종가로 만든250로그수익률의 표본 표준편차다.
거래량0인 날과 그 다음 수익률을 제외하고200개 이상을 요구한다. 시작 시점에 알려진 왕복
위탁수수료·SEC 비용보다 작은 매수 간격은 거부한다. 실제 제품 `validate_drops` 전체와 같다는 뜻은
아니며 미래 수수료 변경·가격 충격·환전비용까지 포함한 손익분기 검사가 아니다.

환율 공표 후7일 제한은 현재 고정한 작은 실행의 정책이다. 정식 장기 탐색 전에는 실제 KRX/NYSE 달력과
MAR 공표 시각의 간격을 대조해 장기 국내 휴장 처리 정책을 확정해야 한다. 현재는7일을 넘으면 실패로
기록하며, 해당 기간·바스켓을 제외하거나 임의 환율을 채워 성과를 계산하지 않는다.

## 재택 PC에서 자료 옮기기

현재 컨테이너에서 재택 PC로 연결되는 원격 환경은 등록돼 있지 않다. 회사에서 새 원격 연결을
설정하지 않아도 퇴근 후 파일 전송으로 이어갈 수 있다. 원본 폴더를 갱신하거나 보류 분할을 다시 만들지 않는다.

재택 PC의 이 저장소 루트에서 아래 명령을 실행한다. `<원본 분할 CSV>`는 `etf_m1/protocol` 아래에
이미 생성된 파일을 사용한다. Windows에서 이 명령 자체는 아직 검증하지 않았다. Python3.12가 필요하다.

```powershell
python -m src.research.etf.m5_inputs `
  --data-root 'C:\Users\leerj\Projects\split-research-data\etf_m1' `
  --split-csv '<원본 분할 CSV의 전체 경로>' `
  --output "$env:USERPROFILE\Desktop\m5-inputs.json" `
  --archive "$env:USERPROFILE\Desktop\etf-m5-inputs.zip"
```

새 JSON·ZIP만 만들며 기존 경로는 덮어쓰지 않는다. ZIP에는 분할 CSV/기록, 메타데이터,
`prices/CURRENT`, 해당 묶음 manifest·일봉 압축 파일, 국내·미국 달력·MAR 환율,
분할에 금이 있으면 금 일봉, 있으면 `protocol/m5_controls.json`을 원래 상대경로로 담는다.
혼합 일봉 파일에는 원래 보류 상품 행도 포함될 수 있다. 원본 파일을 그대로 운반하며 실행 시에는
탐색 상품만 사용한다. ZIP 내부의 바이트도 입력 해시와 대조한다.

완성한 ZIP을 현재 컨테이너 접속에 쓰는 SSH 계정·주소·포트로 SFTP/SCP 전송하면 된다.
주소·포트가 확인되면 그 값으로 전송 명령을 구성한다. 로그인 비밀번호나 인증 코드는 채팅에 올리지 않는다.
예를 들어 Linux의 새 자료 폴더에 풀고 실행한다. 아래 상품 코드는 실제 `explore`의1배 상품으로
지정해야 하며 미확인 코드를 자동 선택하지 않는다.

```bash
unzip etf-m5-inputs.zip -d /자료경로/etf-m5
.venv/bin/python -m src.research.etf.m5_pilot \
  --data-root /자료경로/etf-m5 --manifest /자료경로/etf-m5/m5-inputs.json \
  --symbols <국내코드> <미국코드> \
  --build-dir results/etf-m3-validation/build-v2 \
  --run-dir results/etf-m5-real-pilot-새이름
```

자료가 있어도 단일 가격 봉의 제한폭 여부·분배금 지급일·상폐 공지 근거가 없으면 실행이 실패할 수 있다.
확인값만 `protocol/m5_controls.json`에 기록하고 manifest를 새 이름으로 다시 생성한다.
상폐를 모르겠다는 이유로 종가를 연장하거나 상품을 빼지 않는다. 예시 구조는 다음과 같다.

```json
{
  "locked_status": [{"symbol": "예시", "date": "2022-01-03", "locked": false}],
  "payment_dates": [{"symbol": "예시", "date": "2022-01-03", "pay_at": "2022-01-10T00:00:00+00:00"}],
  "delistings": [{"symbol": "예시", "known_at": "2022-01-01T00:00:00+00:00",
    "last_session": "2022-01-03", "delisting_date": "2022-01-04", "source_sha256": "64자리 근거 해시"}]
}
```

이 값은 사용 가능한 실제 입력이 아니다. 중복 확인값·시간대 없는 시각·유효하지 않은 근거 해시는 거부한다.

## 검증과 실행 산출물

```bash
.venv/bin/python -m examples.etf_m5_demo
.venv/bin/python tools/ci/run_cpu_checks.py
python3 -S tools/ci/run_etf_m3_checks.py --build-dir results/etf-m3-validation/build-v2
```

예제는 실제 휴일이 없는 합성 달력을 쓰며 빠른 연결 검사를 위해2020년 이후 세션을 희소하게 둔다.
실제 장기 자료의 성과나 실제 달력 검증으로 해석하지 않는다. `fixture(..., dense=True)`는 조밀한
합성 자료를 생성한다. 국내 휴일의 T+2는 별도 독립 손계산 검사에서 확인한다.

각 새 실행 폴더는 `provenance.json`, `trials.jsonl`, 설정별 원장·비교 보고서, `summary.json`을 보존한다.
원본/설정/프로토콜/연구 소스 해시, Git 기준 SHA, 합성 여부, 실행시간을 기록하고 매 시도 전후 변조를
확인한다. 실패도 전체 계획 횟수에서 빼지 않으며 실패·중단·누락이 있으면 성공으로 표시하지 않는다.
실자료 실행은 명시한 M3 빌드가 필수이고 빌드/소스/바이너리 해시 불일치는 거부한다.
